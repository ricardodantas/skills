# Codebase Overview

_Generated by the learn-codebase skill on 2026-08-06 at commit `d76601b`._

## Summary
A monorepo of **agent skills** — self-contained, reusable capabilities an AI coding agent
loads on demand to do specialized work. It follows the [`anthropics/skills`](https://github.com/anthropics/skills)
layout so skills publish via [skills.sh](https://skills.sh/ricardodantas/skills) and the Claude
Code plugin marketplace with minimal ceremony. Three skills ship today: `learn-codebase`
(understand an unfamiliar repo), `terminal-screenshots` (reproducible VHS terminal media), and
`podman-browser` (headless JS-page scraping). Users install the bundle and invoke a skill by name.

## Tech stack
- **Languages:** Python 3 (`list_skills.py`), Node.js (`browse.js`), Markdown (skill instructions), VHS `.tape` DSL.
- **Frameworks / runtime:** none for the repo itself; skills shell out to external tools — Playwright/Podman, Charmbracelet VHS.
- **Build / package manager:** none. No `package.json`, `pyproject.toml`, or lockfiles at root — skills are plain files. Packaging/validation is done by the *external* `skill-creator` skill's scripts.
- **Datastores / external services:** none in-repo. `podman-browser` pulls `mcr.microsoft.com/playwright` container; `terminal-screenshots` needs `vhs`/`ttyd`/`ffmpeg`.
- **Skills applied:** `learn-codebase` (this skill) — the repo is small enough that no sub-skills were needed.

## Architecture
Not an application — a **flat catalog of skills** plus a publish manifest. There is no runtime,
build graph, or inter-module coupling; each skill is independent and consumed by an external agent.

    [agent] --loads--> skills/<name>/SKILL.md  (+ optional scripts/ references/ assets/)
       |
       +-- .claude-plugin/marketplace.json  (declares which skills publish)
       +-- template/SKILL.md                 (starting point for new skills)
       +-- AGENTS.md / CLAUDE.md / README.md (conventions + install docs)

Each skill owns: a `SKILL.md` (required, with `name`/`description` frontmatter) and, optionally,
`scripts/` (executable helpers), `references/` (docs loaded on demand), and example assets.

## Key modules
| Path | Responsibility |
| --- | --- |
| `skills/learn-codebase/SKILL.md` | Orchestration skill: discover installed skills, detect stack, select + apply skills, write `docs/CODEBASE_OVERVIEW.md`. |
| `skills/learn-codebase/scripts/list_skills.py` | Dependency-free scanner that parses SKILL.md frontmatter across skill dirs to recover full `name: description` pairs (injected `<available_skills>` is often truncated). Has a `--self-check`. |
| `skills/learn-codebase/references/report-template.md` | Canonical structure for the generated overview (this file follows it). |
| `skills/terminal-screenshots/SKILL.md` | How to author VHS `.tape` files and render terminal screenshots / GIF / MP4 / WebM. |
| `skills/terminal-screenshots/*.tape` | `basic-screenshot.tape`, `demo-recording.tape` — runnable examples. |
| `skills/podman-browser/browse.js` | Self-contained Node CLI: parses args, spawns a Podman Playwright container, returns rendered text or HTML. |
| `skills/podman-browser/SKILL.md` | Usage, options (`--html`, `--wait`, `--selector`), and container/version pinning notes. |
| `.claude-plugin/marketplace.json` | Publish manifest — every shipped skill is listed under `plugins[].skills`. |
| `template/SKILL.md` | Blank frontmatter + heading to bootstrap a new skill. |
| `AGENTS.md` | Authoritative rules for contributors/agents (frontmatter, naming, validation, conventions). |

## Data & control flow
Two representative paths:

1. **`learn-codebase` run** — agent reads `SKILL.md` → runs `scripts/list_skills.py` to enumerate
   installed skills → detects stack from manifests/docs → applies fitting skills → emits an
   in-conversation briefing and writes `docs/CODEBASE_OVERVIEW.md` per `references/report-template.md`.
   `list_skills.py` scans `~/.agents/skills`, `~/.claude/skills`, `./.claude/skills`, `./skills`
   (first occurrence per name wins) and parses YAML frontmatter without PyYAML.

2. **`podman-browser` run** — `browse.js` parses argv (URL + flags) → builds `podman run` args with
   env vars → container does `npm install playwright@<pinned>` then runs an inline Playwright script
   → Chromium loads the URL (`networkidle`), optionally waits for a selector + extra ms → prints
   `document.body.innerText` (or full HTML) to stdout; exit code propagates from the container.

Config/state is per-skill and ephemeral — no shared state, no datastore, no config files.

## Entry points
- **Skill discovery / analysis:** `python3 skills/learn-codebase/scripts/list_skills.py [dirs…]` (`--self-check` for the built-in test).
- **Headless scrape:** `./skills/podman-browser/browse.js [OPTIONS] URL` (symlinked as `podman-browse`).
- **Terminal media:** `vhs skills/terminal-screenshots/<file>.tape`.
- **Publishing:** the agent/plugin host reads `.claude-plugin/marketplace.json`.

## Build, run, and test
No repo-level build. Commands are per-skill; validation/packaging live in the external
`skill-creator` skill (per AGENTS.md).

    # validate a skill's frontmatter/naming/structure (external skill-creator script)
    quick_validate.py skills/<name>

    # package a skill into a git-ignored *.skill archive (external)
    package_skill.py skills/<name> .

    # run the one in-repo self-check
    python3 skills/learn-codebase/scripts/list_skills.py --self-check

    # exercise the scanner against real skill dirs
    python3 skills/learn-codebase/scripts/list_skills.py

    # render a terminal recording
    vhs skills/terminal-screenshots/demo-recording.tape

    # scrape a JS-rendered page
    ./skills/podman-browser/browse.js "https://example.com"

There is no CI workflow (`.github/` absent) and no root test runner.

## Conventions
- **SKILL.md frontmatter has exactly two fields:** `name` and `description`. Nothing else.
- **`name`** is hyphen-case (`[a-z0-9-]`, no leading/trailing/double hyphens) and **must match the folder name**.
- **`description`** states what the skill does *and* when to use it (triggers/keywords), no angle brackets, ≤1024 chars.
- **Keep bodies lean** — long material goes in `references/` and is pointed to from SKILL.md.
- **Registration is required:** a skill isn't "done" until listed in `marketplace.json` and the README Reference section.
- **Non-trivial scripts keep a runnable self-check** (e.g. `list_skills.py --self-check`).
- **`*.skill` archives are build artifacts** — git-ignored, never committed.
- **Commit trailer:** `Co-authored-by: Copilot <223556219+Copilot@users.noreply.github.com>`.
- **Smallest change that fully solves the task**; no speculative abstractions.

## Risks & rough edges
- **Convention drift inside skill folders:** AGENTS.md says *don't* add README/LICENSE inside a skill
  folder, yet `terminal-screenshots/` and `podman-browser/` each ship a `README.md` + `LICENSE`
  (`learn-codebase/` also has a `README.md`). Either the rule or the folders should be reconciled.
- **No automated validation in-repo:** frontmatter/naming rules and the "must be registered in
  marketplace.json" invariant are enforced only by the external `skill-creator` scripts and human
  review — nothing in this repo (no CI, no pre-commit) catches a mismatch.
- **Version coupling in `podman-browser`:** the container image tag and `PLAYWRIGHT_VERSION` in
  `browse.js` must be bumped together; drift silently breaks runs. Documented but manual.
- **`browse.js` inline-script quoting:** the Playwright source is embedded via `node -e '...'` with
  single-quote escaping — fragile if the script grows; no test covers it.
- **VHS font caveat:** custom fonts render with broken letter spacing; `.tape` files must use
  `"monospace"` + `LetterSpacing 0` (documented, easy to forget).
- **Only one skill has a test** (`list_skills.py`); `browse.js` and the `.tape` examples are unverified by any check.

## Glossary / where to look next
- **Skill** — a folder under `skills/` with a `SKILL.md`; the unit of capability an agent loads. Start: `template/SKILL.md`.
- **Frontmatter** — the two-field YAML header (`name`, `description`) validated by convention. Start: `AGENTS.md`, `scripts/list_skills.py:parse_frontmatter`.
- **Marketplace manifest** — publish list of skills. Start: `.claude-plugin/marketplace.json`.
- **User- vs model-invoked** — a skill either runs only when typed or can also be auto-selected by the agent. Start: README "Reference" section.
- **Adding a skill** — the 4-step flow (copy template → write SKILL.md → register in manifest → add to README). Start: `AGENTS.md` "Adding a skill".
